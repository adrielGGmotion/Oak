# Contributing to Beer

We welcome contributions! Here's how to get started.

## Getting Started

1. Fork the repository
2. Create a branch for your changes
3. Make your changes
4. Open a pull request

## Workflow

For any non-trivial change:

1. Open an issue or feature request to discuss the change first
2. Once agreed, create a feature branch from `main`
3. Implement your changes, keeping commits to one logical change each
4. Open a pull request targeting `main`
5. Ensure CI passes
6. Request a review from a maintainer or AI reviewer

For tiny/simple fixes (a few lines, obvious), direct pushes to `main` are fine.

## Code Style

- Follow the existing code conventions in the project
- Kotlin: use the official Kotlin style guide where possible
- Keep methods focused and reasonably sized

## Pull Request Guidelines

- One logical change per PR
- Reference related issues in the description
- Keep the scope focused — avoid mixing refactors with features
- Update documentation if needed

## Code of Conduct

Be respectful and constructive. We're all here to build something cool.
